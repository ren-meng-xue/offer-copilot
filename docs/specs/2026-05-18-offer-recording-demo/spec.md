# Spec: Offer 项目录制 Demo 原型

**日期：** 2026-05-18
**状态：** Draft
**关联原型：** `docs/specs/2026-05-18-offer-recording-demo/flow.html`

---

## 目标

为 Offer 项目的录制视频准备一套前端原型脚本，用顶部原型导航组织登录 / 注册、上传知识、索引完成、聊天问答等关键步骤，并保持与当前前端 UI 的视觉风格一致。

---

## 核心流程

1. 打开录制 demo 原型，默认进入「登录注册」screen。
2. 展示登录和注册的表单状态，体现品牌侧栏、浅色工作台、蓝色主操作按钮。
3. 切换到「上传知识」screen，展示 URL 导入和文件上传入口。
4. 切换到「索引完成」screen，展示知识库数量、切片数量、完成状态。
5. 切换到「聊天问答」screen，在同一个真实会话里连续展示三类问题：
   - 询问天气：展示工具型回复，不需要知识库引用。
   - 询问知识库多少个：展示知识库统计回复。
   - 询问知识库相关问题：展示带引用来源的 RAG 回复。
6. 切换到「录制脚本」screen，查看推荐镜头顺序、重点颜色和录制提示。

---

## 方案比较

### 方案 A：独立静态 HTML 原型

- 实现思路：在 `docs/specs/.../flow.html` 中写自包含 HTML / CSS / JS，模拟当前 UI 的页面、tab、消息和知识库状态。
- 风险：不会直接复用 React 组件，和真实页面存在少量细节差异。

### 方案 B：新增 Next.js 原型页面

- 实现思路：在 `frontend/` 中增加专门路由，复用现有组件和样式。
- 风险：会进入业务实现范围，需要更多测试与路由权限处理，不适合当前「先画原型」阶段。

### 方案 C：只写 Markdown 脚本

- 实现思路：仅用文档描述录制步骤和颜色。
- 风险：无法直观看到 tab、布局和聊天状态，录制前沟通成本高。

**推荐方案：** 方案 A。当前用户明确要求先画原型 HTML，独立文件可直接打开验证，不影响现有前端。

---

## 技术方案

- **采用方案：** 独立静态 HTML 原型。
- **关键决策理由：** 快速表达录制 demo 的结构、镜头和颜色，不引入前端路由与接口变更。
- **依赖的现有模块：** 参考 `frontend/src/app/globals.css`、`auth-shell.tsx`、`app-shell.tsx`、`chat-page.tsx`、`knowledge-page.tsx` 的视觉语言。

## 页面结构

| Screen | 目的 | 主要内容 |
|---|---|---|
| 登录 / 注册 | 展示首次进入与账号创建 | 品牌侧栏、登录表单、注册表单预览 |
| 上传知识 | 展示知识库准备过程 | URL 导入、文件上传 |
| 索引完成 | 展示资料已可问答 | 3 个知识库、128 个切片、100% 索引完成 |
| 聊天问答 | 展示 demo 核心能力 | 同一会话内连续展示天气、知识库数量、知识库问题三轮消息 |
| 录制脚本 | 给录屏人员使用 | 镜头顺序、颜色标记、话术摘要 |

## 边界 & 不做的事

- 做：录制视频 demo 的静态 HTML 原型。
- 做：用顶部原型导航拆分登录 / 注册、上传知识、索引完成、聊天问答、录制脚本。
- 做：聊天问答保持同一个会话，贴近现有前端聊天页布局。
- 做：明确天气、知识库数量、知识库相关回复的展示颜色。
- 不做：接入真实登录、上传、聊天接口。
- 不做：实现浏览器录屏、视频导出或媒体存储能力。
- 不做：修改现有 Next.js 页面。
