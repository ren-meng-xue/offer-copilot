# Changelog - 2026-06-05

## 问题修复：解决生产环境登录 502/挂起问题

### 现象
- 前端登录接口 `POST /auth/login` 对于正确的密码会无限挂起，最终导致 Vercel 代理层超时返回 502 ROUTER_EXTERNAL_TARGET_ERROR。
- 随后导致后端的整个 `uvicorn` 事件循环（Event Loop）线程被完全卡死，任何后续请求（包括非数据库依赖的 `/health`）也无法正常响应。
- 密码错误的登录请求能够快速返回 401（因为未进入密码校验环节）。

### 根因分析
1. **系统熵不足导致挂起**：Debian-slim 镜像部署在 Render 的轻量容器环境时，由于缺乏足够的系统随机熵源，导致 `bcrypt` 底层在依赖系统 `getrandom` 库时被阻塞，进而挂起整个进程。
2. **事件循环同步阻塞**：`bcrypt.checkpw`（原 `verify_password`）是一个极度消耗 CPU 且完全同步的操作。在单线程 ASGI 事件循环中直接调用此函数，会彻底锁死事件循环，从而在该请求执行期间，后端无法处理任何其他 I/O。

### 修复方案
1. **Docker 系统依赖**：在 `backend/Dockerfile` 中显式安装 `ca-certificates`（提供 HTTPS/SSL 支持）和 `haveged`（提供持续的系统熵源）。
2. **初始化启动 haveged**：在 `backend/start-combined.sh` 首行启动 `haveged -w 1024`，保证容器在初始化和运行期拥有充足的系统熵。
3. **哈希轮数优化**：在 `security.py` 中显式设置 `bcrypt.gensalt(rounds=10)`，在保证加密强度的同时，极大加速在受限 CPU 云容器下的验证计算效率。
4. **异步化验证**：在 `security.py` 封装 `verify_password_async` 异步包装函数，使用 `asyncio.to_thread` 将同步阻塞的 `bcrypt.checkpw` 丢到线程池执行，确保其不阻塞 FastAPI 的主事件循环。
5. **服务调用适配**：修改 `auth_service.py`，将 `login_user` 中的密码比对逻辑改为 `await verify_password_async`。
